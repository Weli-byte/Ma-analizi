# ADR 0011: Dependency reproducibility

## Status
Accepted — 2026-09-26.

## Context
`requirements.lock` was an un-hashed `pip freeze` from Windows/Python 3.14; `requirements.txt` duplicated
`pyproject.toml`.

## Decision
- `pyproject.toml` is the single dependency source. `requirements.lock` is a **universal, hash-pinned** lock
  generated by `uv pip compile pyproject.toml --extra dev --universal --generate-hashes --python-version 3.12`.
- Supported Python: 3.12 and 3.14 (CI matrix). Python 3.13 is expected to work but is not tested.
  OS: Linux (CI) and Windows 11 (developer machine).
- Install: `pip install --require-hashes -r requirements.lock && pip install --no-deps -e .`.
- A CI job (`lock-up-to-date`) fails when the lock drifts from `pyproject.toml`.
- `dependency_lock_hash` (sha256 of the lock) is stored in every experiment record.

## Alternatives
Poetry/PDM (rejected: extra tooling); unpinned ranges (rejected: non-reproducible).

## Consequences
Dependency changes must regenerate the lock in the same commit.
